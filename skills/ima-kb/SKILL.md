# 我的 ima 知识库速查

## ★ 怎么读（先用这一节，别整篇读）

优先用本机面板插件 `dsh-ima-kb-panel` 的三个工具，它们有界、带字符偏移量、不会把上下文撑爆：

| 工具 | 用途 |
|---|---|
| `kb_list` | 列出全部笔记（标题、note_id、字符数、开头预览） |
| `kb_search(query, note_id?, limit?)` | 在**全部笔记正文**里做精确子串检索，返回片段 + 字符偏移量 |
| `kb_read(note_id, offset?, limit?)` | 按偏移量读取正文，默认 6000 字，末尾给出下一段 `offset` |
| `kb_find(query, start?)` | ima **官方分词检索**：换一种说法也能找到，返回命中的笔记列表（note_id + 开头预览），配合 `kb_read` 用 |
| `kb_space_list` / `kb_space_browse` / `kb_space_search` | 个人知识库侧：列知识库 / 浏览文件夹文件 / 按文件名检索（不搜正文） |

典型流程：`kb_search`（精确）或 `kb_find`（换说法）定位 → `kb_read(note_id, offset)` 读上下文。

**不要**用 `mcp__ima-kb__get_note_content` 读这些大笔记：它没有分页参数，一次返回整篇（最长 54.8 万字符），会直接把上下文撑爆。

侧边栏还有一个「ima 知识库」入口，可以随时浏览、全文检索、滚动阅读，不消耗模型上下文。

## ⚠️ 实测结论：知识库搜索 vs 笔记搜索

- **知识库** `search_knowledge`：**只索引标题**。API 新上传的文件正文独有词也搜不到，`highlight_content` 恒为空。
- **笔记** `search_notes` + `search_type:"content"`：**真全文检索**，返回 `<em>` 高亮，但每篇笔记只回一段。
- **结论**：要让内容按正文可检索，必须做成**笔记**；要一次拿到同一篇里的多处命中，用 `kb_search`（本地子串匹配，一篇可回多段）。
- 面板 v1.4.0 起 `kb_list` / `kb_search` 自动翻页 + 串行节流（约 800ms/次），**覆盖全部笔记**；进程启动后后台预热正文约 1~2 分钟，首次字面检索偶尔会提示「结果可能不全」；字面无命中时面板会自动补一轮官方分词检索（`kb_find`）。
- `list_note` 返回的标题元数据会被截断到约 30 字符并加「...」；按标题找笔记要用前缀匹配（正文 h1 是完整标题）。

## 📏 笔记能力实测

| 项 | 数值 |
|---|---|
| 单篇内容上限 | 约 **10 MiB**（format=2 的 content 长度 ≈ 10,485,760 字符），超限 append 返回 code=141，只能拆篇 |
| 单次 append 建议 | 图片 ≤ 6 张/批、content ≤ 900KB；**纯空白 content 返回 210001** |
| 图片写入 | markdown `![caption](data:image/jpeg;base64,...)`，单图 < 3 MiB，写入后成为 `cursor-side` 图片块（按位置排列） |
| 大笔记全文索引 | ✅ 有效 |
| 导入速度 | 约 2.4s/万字（含图片时按图片数） |
| 检索类型 | 关键词全文检索 + 高亮，**非语义** |
| `get_doc_content` 分页 | ❌ 没有 offset/limit，整篇返回 |
